1. Signals & linkedSignal()

Signals are a modern reactive primitive in Angular that represent stateful values. When a signal changes, Angular automatically updates the UI.

linkedSignal() allows one signal to derive its value from another while remaining reactive.

Key benefits of signals:
  • Fine-grained reactivity
  • No manual subscriptions
  • Better performance than traditional change detection

2. Signal-Based Components

Signal-based components use signals directly inside component classes to manage state instead of class properties or RxJS subscriptions.

This approach results in:

  • Simpler component logic
  • Automatic UI updates
  • Reduced boilerplate code

3. Computed Signals & Effects

Computed signals derive values from other signals and recompute automatically when dependencies change.

Effects are used to perform side effects such as logging, API calls, or DOM interactions when signals update.

Best practices:
  • Use computed signals for derived state
  • Use effects only for side effects
  • Avoid heavy logic inside effects

4. RxJS Basics & Operators

RxJS is a reactive programming library based on Observables. It is heavily used in Angular for handling asynchronous operations.

Common RxJS operators include:

  • map
  • filter
  • switchMap
  • mergeMap
  • catchError

RxJS excels in handling complex async workflows such as API streams and real-time data.

5. Observables vs Signals

Both Observables and Signals support reactive programming, but they serve different purposes.

Key differences:
  • Signals are synchronous and state-focused
  • Observables are asynchronous and stream-focused
  • Signals do not require subscriptions
  • Observables are ideal for HTTP and event streams

Modern Angular applications often use Signals for UI state and RxJS for async operations.
