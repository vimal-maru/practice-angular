1. Creating Services

Services in Angular are used to encapsulate business logic, data access, and reusable functionality that should not live inside components.

They promote separation of concerns and help keep components lightweight and focused on the UI.

Common responsibilities of services:
  • Fetching data from APIs
  • Sharing data between components
  • Encapsulating business rules

2. Dependency Injection Patterns

Dependency Injection (DI) is a core Angular design pattern that allows classes to receive dependencies from an external source rather than creating them directly.

This improves code reusability, testability, and maintainability.

  • Constructor-based injection
  • Service abstraction using interfaces
  • Loose coupling between components and services

3. HttpClient & HTTP Interceptors

The HttpClient service is used to communicate with backend APIs using HTTP methods such as GET, POST, PUT, and DELETE.

HTTP interceptors allow you to intercept and modify HTTP requests and responses globally.

Common interceptor use cases:
  • Adding authentication tokens
  • Centralized error handling
  • Request and response logging

4. Service Providers & Hierarchical Injection

Angular uses a hierarchical injector system to determine how and where services are instantiated and shared.

Providers can be registered at different levels, affecting service scope and lifetime.

Provider scopes include:
  • Application-wide (singleton)
  • Feature-level
  • Component-level

5. State Management with Services

Services can act as a lightweight state management solution by holding shared state and exposing it to multiple components.

This approach is often used for small to medium-sized applications where a full state management library is not required.

Typical scenarios:
  • User authentication state
  • Shared UI preferences
  • In-memory caching of API data
