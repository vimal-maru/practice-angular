1. Change Detection Strategies

Angular uses a change detection mechanism to keep the UI in sync with application state. By default, Angular checks the entire component tree for changes.

Understanding change detection is critical for building high-performance applications.

Key points:
  • Default strategy checks all components
  • Frequent checks can impact performance
  • Optimization reduces unnecessary re-rendering

2. OnPush Optimization

The OnPush change detection strategy tells Angular to check a component only when its inputs change or an explicit event occurs.

This significantly improves performance for large and complex UIs.

When to use OnPush:
  • Immutable data patterns
  • Pure components
  • Signal-based state updates

3. Lazy Loading & Code Splitting

Lazy loading and code splitting reduce the initial bundle size by loading application features only when required.

This leads to faster startup times and better user experience.

Benefits:
  • Smaller initial JavaScript payload
  • Faster page load
  • Improved scalability

4. Tree Shaking & Bundle Optimization

Tree shaking is a build-time optimization that removes unused code from the final production bundle.

Angular’s build process automatically applies tree shaking when creating production builds.

Optimization techniques:
  • Use ES modules
  • Avoid unused imports
  • Prefer standalone components

5. Virtual Scrolling & CDK

Virtual scrolling renders only the visible portion of large data sets, improving performance and reducing memory usage.

The Angular Component Dev Kit (CDK) provides utilities to implement virtual scrolling efficiently.

Ideal use cases:
  • Large lists or tables
  • Infinite scrolling views
  • High-performance dashboards
